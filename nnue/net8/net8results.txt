Net8 methodology
================

Goal: switch architecture instead of continuing to fine-tune Chess768/256.

Current best baseline
=====================

Selected checkpoint: net5 iter064.

Direct net5 iter064 strength vs HCE:
- 10+0.1: +236.8 +/- 24.5 Elo
- 90+0.5: +220.1 +/- 42.5 Elo

Anchored net5 iter064 estimate from Elo.md:
- 10+0.1: 2889.5 +/- 27.1
- 90+0.5: 2954.6 +/- 47.1

Why net8 exists
===============

Net5 found the best current Chess768/256 checkpoint. Net6 and net7 then showed that
continuing to train from that checkpoint does not reliably improve it:

- net6 controlled 50/50 HCE/NNUE continuation failed immediately.
- net7 controlled 80/20 HCE/NNUE continuation also failed immediately.

This suggests LR tweaks are unlikely to be the next major lever. The current
architecture is probably the bottleneck. Net8 changes architecture and trains from
scratch.

Architecture plan
=================

Target:
- King-bucket NNUE.
- 8 king buckets first.
- Hidden size 256.
- Output size 1.
- Keep scale 400 initially.

Reason:
- Chess768 has no explicit king-region specialization.
- King buckets should improve king safety, attacks, and phase-dependent structure
  without jumping straight to a much larger/slower 512-wide net.
- 8 buckets is the best first step: meaningful extra structure without making the
  integration and speed risk too large.

Data and toolchain plan
=======================

Use 80/20 HCE/NNUE, not 50/50.

Reason:
- 50/50 was bad in net6.
- 80/20 was less bad in net7, and is safer as a conservative architecture test.
- Since architecture is the variable, do not also make the data distribution aggressive.

Planned data:
- Shared-disk multi-worker setup.
- 5 workers.
- 5M positions per chunk.
- 40 chunks per worker unless stopped early.
- 1B total positions if all chunks complete.
- 10k-node labels.
- WDL=0.1.
- 80% HCE-generated data.
- 20% NNUE-generated data from net5 iter064.

Toolchain:
- SHAYVERI datagen still writes legacy text/plain lines:
  `fen | score | wdl`.
- Bullet utilities replace Marlinflow for conversion and shuffling:
  `bullet-utils convert --from text`.
- Marlinflow is no longer in the net8 critical path.
- Bullet handles KB8 training.
- Bullet checkpoints are converted with `nnue/convert_bullet.py`, which wraps
  Bullet `quantised.bin` in the SHAYVERI `.nnue` header/layout.

Implementation:
- Workers generate two NNUE chunks followed by eight HCE chunks in each 10-chunk cycle.
- Worker chunk directories are prefixed with source: `nnue_...` or `hce_...`.
- Each chunk writes `source=nnue` or `source=hce` in metadata.
- The master claims chunks by source slot:
  - iterations 0-1 in each 10-iteration block require NNUE chunks.
  - iterations 2-9 in each 10-iteration block require HCE chunks.
- If the required source is not ready, the master waits.

Training plan
=============

This is a from-scratch architecture run.

Planned defaults:
- Train id: `shayveri_v2.7_kb8`.
- NFS root: `~/nnue_v2_7`.
- Data root: `~/nnue_v2_7/data`.
- Output root: `~/nnue_v2_7/out`.
- No resume checkpoint.
- LR: 0.001.
- LR drop: 0.0003 after 100 chunks.
- second LR drop: 0.0001 after 200 chunks.
- epochs per chunk: 1.
- batch size: 16384.
- WDL: 0.1.
- scale: 400.
- save every epoch.

Script note:
- `BULLET_UTILS` defaults to `~/bullet/target/release/bullet-utils`.
- `BULLET_DIR` defaults to `~/bullet`.
- `BULLET_PACKAGE` defaults to `bullet_lib`.
- `BULLET_EXAMPLE` defaults to `shayveri_kb8`.
- `BULLET_FEATURES` defaults to `cuda`.
- `BULLET_TRAIN_CMD` defaults to
  `cargo run --release --package bullet_lib --example shayveri_kb8 --features cuda`.
- `BULLET_PREFLIGHT_CHECK` defaults to `1`, so the master runs
  `cargo build --release --package bullet_lib --example shayveri_kb8 --features cuda`
  before claiming any chunk.
- If `CUDA_PATH` is unset and `/usr/local/cuda` exists, the master exports
  `CUDA_PATH=/usr/local/cuda`.
- The master passes these environment variables to the trainer:
  `DATA_FILES`, `TRAIN_ID`, `OUT_DIR`, `RESUME`, `KING_BUCKETS`, `LR`, `EPOCHS`,
  `BATCH_SIZE`, `WDL`, `SCALE`, `SAVE_EPOCHS`, and `TRAIN_EXTRA_ARGS`.
- `DATA_FILES` is colon-separated.
- `TRAIN_EXTRA_ARGS` is available for architecture-specific trainer flags.

Validated setup
===============

- `nnue/shayveri_kb8.rs` is the canonical Bullet trainer example.
- The example is registered in `~/bullet/crates/bullet_lib/Cargo.toml`.
- The master uses a pre-backend-rewrite Bullet checkout because the current
  backend requires CUDA symbols missing from the installed CUDA 11.8 toolkit.
- The old backend needed two local compatibility patches:
  - remove `ctx.set_blocking_synchronize()` from `crates/bullet_cuda_backend/src/device.rs`;
  - compile NVRTC kernels with `-default-device` and `--std=c++17`.
- Runtime smoke passed:
  - one `.plain` row converted with `bullet-utils convert --from text`;
  - shuffled with `bullet-utils shuffle`;
  - trained with `cargo run --release --package bullet_lib --example shayveri_kb8 --features cuda`;
  - saved `[runtime_smoke-1]`.
- Master is running after the runtime smoke passed.
- Still verify after launch that first 10 done chunks contain 2 NNUE and 8 HCE.

Checkpoint testing plan
=======================

Because this is from scratch, early checkpoints may be weak. Do not kill as fast as
net6/net7 unless results are catastrophically bad.

Suggested testing:
- Convert and test iter019, iter039, iter059, iter079.
- First compare against HCE, not net5.
- Once a checkpoint clears HCE comfortably, compare against net5 iter064.
- If a checkpoint gets within 50 Elo of net5, continue deeper.
- If no checkpoint beats HCE by iter080, stop and debug architecture/trainer/converter.

Expected signal
===============

Reasonable target:
- Match or slightly beat net5 iter064 after enough data.

Great outcome:
- +50 Elo or more over net5 iter064.

Failure signal:
- Cannot clearly beat HCE after 60-80 chunks.
- Conversion/inference scale looks wrong.
- NPS drop is too large to preserve search strength.

Launch notes
============

- Master now preflights the Bullet target before claiming chunks.
- The Bullet example must not call `.output_buckets(Single)`; single output is
  the default in this Bullet version.
- The Bullet example uses the single-output builder signature:
  `.build(|builder, stm_inputs, ntm_inputs| ...)`, with no output-bucket select.
- CUDA 11.8 links failed with missing `cuFuncLoad`; this Bullet CUDA backend needs
  a newer CUDA toolkit/driver API or an older compatible Bullet backend.
- For the pre-backend-rewrite Bullet checkout, the saved-format store already
  exposes `values` as `Vec<f32>`, so the trainer uses
  `store.get("l0f").values.repeat(...)` instead of `.values.f32().repeat(...)`.
- The trainer saves output weights at scale 255 and output bias at scale
  255 * 255 so the produced `.nnue` matches SHAYVERI's current forward pass.
- SHAYVERI's king-bucket mapping was corrected to match Bullet's
  `ChessBucketsMirrored` bucket layout. The previous folded-file mapping made
  KB8 inference incompatible with Bullet-trained weights.
