Net13 methodology
=================

Goal
====

Get SHAYVERI back onto a credible path toward 3400+ by changing the training
signal, not just the net number.

The first twelve nets show that ordinary self-play continuation is saturated.
Net13 should be a controlled reset around the last trusted release baseline,
net5_final.nnue, with stronger self-referential labels and hard anchor gates.

Current read of the evidence
============================

The formal Elo file says net5 gained about +63.5 Elo at 10+0.1 and +57.8 Elo at
90+0.5 over SHAYVERI HCE. That is real, but far below the target curve.

After net5, the apparent gains were mostly internal:
- Net6 and net7 resumed Chess768/256 from net5 and regressed immediately.
- Net8/net10 looked promising against their own KB8 relatives, but later HCE
  sanity checks showed the KB branch was not actually anchored above HCE.
- Net12 KB16 repeated the same broad failure in a more obvious way: it never got
  close to net5, and even HCE was far ahead.

So the honest current baseline is net5_final.nnue, not the KB branch.

Why progress stalled
====================

Main diagnosis:

1. The 10k-node labels are too weak for the target.
   They are good enough to teach a first NNUE to imitate SHAYVERI search, but
   after net5 they mostly recycle the same horizon and eval biases. More
   positions from the same teacher/search budget mostly add volume, not new
   chess strength.

2. Continuation training overwrites good checkpoints too quickly.
   Net6, net7, net9, net10, and net11 all show the same pattern: the useful
   signal is early or absent, and later chunks drift away. Net10's gain happened
   around iter001-iter010; longer training hurt.

3. Internal family tests became misleading.
   Fast 0.5+0.05 pools and same-branch matches made KB8 look much better than it
   was. The HCE gate exposed the truth. Net13 must treat HCE/net5/SF2850 anchors
   as early gates, not as late validation.

4. Bucket-count-only architecture changes did not solve the real issue.
   KB8 and KB16 increased structure but did not transfer into anchored strength.
   More buckets without a stronger teacher and stricter validation is just a
   larger self-play echo chamber.

5. The data distribution is too narrow.
   Current datagen follows the engine's own best move after a short search and
   saves quiet positions. That creates lots of positions, but too few hard
   mistakes, alternatives, defensive resources, or positions where the parent is
   uncertain.

Net13 principle
===============

Train self-referentially, but make the self stronger.

"Self-referential" should mean:
- All training data is generated by SHAYVERI family engines.
- No external engine labels, no Stockfish-eval teacher, no imported games as
  truth.
- It is still allowed to use SHAYVERI at deeper search, SHAYVERI-vs-SHAYVERI
  disagreements, and SHAYVERI HCE as an internal anchor.

Net13 should therefore use self-distillation from deeper SHAYVERI search, not
another pass of shallow 10k-node imitation.

Chosen direction
================

Primary net13 run: Chess768/256 recovery with deep self-distillation.

Do not start net13 with KB8/KB16 or wider hidden size. First prove that the
training signal itself can beat net5 in the known-good classic architecture. If
we cannot improve the safe architecture with a stronger teacher, a larger
architecture will mostly hide the same failure for longer.

Parent:
- net5_final.nnue.

Architecture:
- Chess768/256.
- Existing classic NNUE indexing only.
- No king buckets for the main run.

Trainer:
- Prefer the Marlinflow classic path for net13 mainline, because it is the path
  that produced net3 and net5.
- Keep Bullet only as a side experiment after the mainline clears anchors.

Data recipe
===========

Use two data lanes.

Lane A: balanced baseline self-play
- Generator: SHAYVERI net5 and SHAYVERI HCE.
- Source mix: 70% net5, 30% HCE.
- Generation search: 10k nodes, same as historical runs.
- Purpose: preserve the net5 distribution and prevent catastrophic drift.

Lane B: deep relabel / hard-position distillation
- Generator: SHAYVERI net5, with some HCE games for diversity.
- Labeler: SHAYVERI net5 at much higher search.
- Target search budget: start with 100k nodes; test 300k nodes if throughput is
  acceptable.
- Positions: emphasize parent-uncertain and parent-error positions:
  - positions where shallow 10k and deep 100k scores differ by >= 80 cp;
  - positions where best move changes between shallow and deep search;
  - positions with score near equality, roughly -150 to +150 cp;
  - positions from losses/draw collapses versus HCE/net5 mirrors;
  - quiet positions only, preserving the existing no-capture/no-promo filter.
- Purpose: teach the net what deeper SHAYVERI search discovers, not just what
  shallow SHAYVERI already believes.

Initial mix:
- 60% Lane A baseline.
- 40% Lane B deep/hard.

If early checkpoints lose to net5 but beat HCE:
- Move to 75% Lane A / 25% Lane B.

If early checkpoints tie net5 and are color-balanced:
- Move to 50% Lane A / 50% Lane B for one short branch.

Training recipe
===============

This is not a long continuation run.

Suggested initial settings:
- Resume from the net5 PyTorch checkpoint if available.
- If the checkpoint is not available, reconstruct from net5_final.nnue before
  training or run a short reproduction pass first.
- LR: 0.00001 to 0.00003.
- Epochs per chunk: 1.
- Batch size: 16384.
- WDL: 0.1.
- Scale: 400.
- Chunk size: 1M positions.
- Save every chunk.
- Stop after 20 chunks unless the anchor gates are already positive.

Reason:
- Previous continuation runs show that useful updates appear early and then
  regress.
- Net13 should sample many tiny branches instead of betting everything on one
  1B-position line.

Branch matrix
=============

Run short branches, then promote only the branch that clears anchors.

Branch 13A:
- 70/30 net5/HCE generation.
- 60/40 baseline/deep-hard data.
- LR 0.00001.

Branch 13B:
- Same data as 13A.
- LR 0.00003.

Branch 13C:
- 90/10 net5/HCE generation.
- 50/50 baseline/deep-hard data.
- LR 0.00001.

Branch 13D:
- 50/50 net5/HCE generation.
- 75/25 baseline/deep-hard data.
- LR 0.00001.

Kill each branch by iter010 if it is clearly worse than net5 at 10+0.1 or has a
bad color split.

Script implementation
=====================

Net13 scripts live in `nnue/net13/`:

- `branch_config.sh` encodes the 13A-13D branch matrix.
- `worker_generate_chunks.sh` produces baseline and deep-hard chunks.
- `deep_relabel.py` implements the deeper self-search hard-position filter.
- `master_train_chunks.sh` consumes chunks in the same branch pattern and trains
  the classic Marlinflow Chess768/256 path.
- `convert_checkpoint.sh` converts a Marlinflow checkpoint JSON to `.nnue`.
- `run_gate_matches.sh` runs the net5, HCE, SF2850, and LTC gates.

Pattern tokens:
- `N`: net5 baseline chunk.
- `H`: HCE baseline chunk.
- `D`: net5 deep-hard chunk.
- `E`: HCE-generated deep-hard chunk, relabelled by net5.

Branch patterns:
- 13A: `NNNNHHDDDE` = 70/30 net5/HCE and 60/40 baseline/deep-hard.
- 13B: `NNNNHHDDDE` with higher LR.
- 13C: `NNNNHDDDDD` = 90/10 net5/HCE and 50/50 baseline/deep-hard.
- 13D: `NNNNNNNNHHHHHHHDDEEE` = 50/50 net5/HCE and 75/25 baseline/deep-hard.

The worker and master both source `branch_config.sh`; use the same `BRANCH`
value for both sides.

Testing gates
=============

Gate 0: sanity before training
- Re-pin net5_final.nnue vs SHAYVERI_HCE at 10+0.1 using the current binaries.
- Re-pin net5_final.nnue vs SF2850 at 10+0.1 with the current test harness.
- Save exact command lines, binaries, hashes, options, and book.
- If this does not reproduce the Elo.md picture within expected noise, fix the
  harness before training.

Gate 1: every early checkpoint
- Convert and test iter001 through iter010.
- Minimum test: 800 games vs net5 at 10+0.1.
- Track White and Black separately.

Gate 2: HCE anchor
- Any checkpoint that is even roughly tied with net5 must immediately test vs
  SHAYVERI_HCE at 10+0.1.
- It should crush HCE. If it does not, reject it even if it beats a sibling.

Gate 3: SF2850 anchor
- Any checkpoint that beats net5 by >= +20 Elo at 10+0.1 must test against
  SF2850.
- The practical target is to move net5's STC score vs SF2850 from about 40.1%
  toward 45%+.

Gate 4: 90+0.5
- Only candidates that pass Gates 1-3 get LTC.
- A candidate that is +30 STC but negative LTC is not a release, though it can
  be kept as a specialist reference.

Promotion target
================

Minimum net13 success:
- +30 Elo over net5 at 10+0.1.
- No regression at 90+0.5.
- Clear HCE domination.

Strong net13 success:
- +60 to +100 Elo over net5 at 10+0.1.
- Positive or neutral LTC.
- SF2850 score moves close to parity at LTC and meaningfully improves at STC.

What gets us back on track:
- A repeatable deep-label pipeline that gives +50 Elo per cycle.
- Once that is proven in Chess768/256, net14 can spend the same stronger signal
  on a larger architecture.

If net13 fails
==============

Do not run net14 as "more net13."

If all Chess768/256 deep-distillation branches fail, the bottleneck is probably
capacity. Then the next move should be:
- implement variable hidden size cleanly in loader, converter, scalar, and AVX2;
- train Chess768/512 from scratch or via net surgery from net5;
- use the exact same deep/hard self-distillation gates from net13.

If net13 succeeds
=================

Promote the best checkpoint only after HCE, net5, SF2850, and LTC gates.

Then net14 should be:
- same data pipeline;
- larger classic architecture first, likely Chess768/512;
- only then revisit bucketed layouts.

The main lesson is that 3400+ will not come from net numbering. It needs a
ratchet: deeper self labels, hard-position mining, strict anchors, and small
promotions that cannot fool themselves.
